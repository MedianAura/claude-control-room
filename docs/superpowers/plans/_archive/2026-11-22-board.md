# Le tableau (tests et TODO au format control-room) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Steps tagged `(user)` are checked by the user in their real setup.

**Goal:** Remplacer la lecture des tests `(user)` et du `## To do` du plan maître par un tableau JSON par projet, écrit
par le seul serveur, alimenté par l'orchestratrice via MCP, affiché groupé et pondéré, cité par `#XXXX`.

**Architecture:** `lib/board.js` porte le modèle (lecture, mutations atomiques, identifiants, vue groupée, citations)
sans rien savoir du HTTP. `lib/board-routes.js` l'expose aux outils MCP (secret client). `lib/right.js` bascule la
colonne de droite et `/api/test` sur le tableau ; toute livraison à l'orchestratrice passe par `withRefs` qui
développe les `#XXXX`.

**Tech Stack:** Node 24 built-ins, `node:test`, page en un fichier (`plugin/ui/index.html`).

**Spec:** `docs/superpowers/specs/2026-11-22-board-design.md` (amende `2026-11-21-control-room-design.md`).

## Global Constraints

- Node built-ins uniquement, pas de `npm install` ; JSON, pas de YAML.
- Tests : `node --test` (pas `node --test test/`), toujours avec `CONTROL_ROOM_DIR` temporaire (`tempStateDir`).
- Écriture du tableau atomique (tmp + `rename`), dossier créé au besoin ; le serveur est son seul écrivain.
- Identifiant : 4 caractères dans `23456789ABCDEFGHJKMNPQRSTUVWXYZ`, unique dans le fichier, éléments fermés compris.
- Poids : `high` | `medium` | `low`, absent = `medium`.
- Secret client : crée, modifie, ferme une entrée TODO, rouvre ; **jamais** `state: ok` sur un test. Secret de la page :
  OK / KO.
- Le serveur n'écrit dans aucun fichier du projet autre que le tableau.
- Aucun test ne doit dépendre de `F:\AzerothCoreCOA` ni d'un chemin de projet réel.
- `plugin/ui/index.html` est en cours de refonte (passe de design, autre session) : la tâche 3 part de son commit.
- Commits sur `main`, messages en français, préfixes `feat:` / `docs:` / `test:` comme l'historique.

## Review Focus

- Tableau cassé à la main (JSON invalide) pendant que le serveur tourne : aucune écriture, la colonne dit pourquoi
  (tâche 1 `refuses to write an unreadable board`, tâche 3 `an unreadable board is shown, not emptied`).
- Double clic sur OK : le second répond 409, une seule livraison, pas de double « propose l'archivage » (tâche 3
  `a second OK on the same test is refused and delivers nothing`).
- `#45bg` en minuscules, `#45BGX` collé à un mot, `#ZZZZ` inconnu, le même id cité deux fois : développé une fois,
  seulement s'il existe (tâche 1 `refsBlock expands known ids once, case-insensitive, whole tokens only`).
- Test dont le plan n'est pas (ou plus) dans `active-plans.json` : groupé sous son nom, jamais perdu (tâche 1
  `view keeps tests whose plan is not active, under the plan name`).
- `.control-room/` absent au premier `add_test` : créé (tâche 1 `creates the board and its folder on first write`).

### Task 1: Modèle du tableau (`lib/board.js`)

**Files:**
- Create: `plugin/lib/board.js`
- Test: `test/board.test.js`

**Interfaces:**
- Consumes: rien (seulement `fs`, `path`, `crypto`).
- Produces :
  - `class BoardError extends Error { code }` ; `code` ∈ `'not-found' | 'invalid' | 'state' | 'unreadable'`.
  - `readBoard(file: string): { items: Item[], error: string | null }` — fichier absent : `{ items: [], error: null }` ;
    JSON invalide ou sans tableau `items` : `{ items: [], error: <message> }`.
  - `addItem(file, kind: 'test' | 'todo', fields): Item` — champs test `{text, detail?, weight?, plan?, task?, origin?}`,
    TODO `{text, detail?, weight?, group?, plan?}`. Pose `id`, `state: 'open'`, `notes: []`, `createdAt` (ISO),
    `closedAt: null` ; champs absents → `null` (`weight` absent → omis, lu comme `medium`).
  - `updateItem(file, id, fields): Item` — mêmes champs que `addItem` pour son `kind`, sauf `text` vide ; jamais `id`,
    `kind`, `state`, `notes`.
  - `closeTodo(file, id, state: 'done' | 'dropped', note?: string): Item`
  - `addNote(file, id, text, by: 'orchestrator' | 'user'): Item`
  - `removeItem(file, id, reason): Item` — `state: 'removed'`, note `by: 'orchestrator'` avec la raison.
  - `reopenItem(file, id, reason): Item` — test `ok` ou TODO `done`/`dropped` → `open`, `closedAt: null`, note.
  - `tickTest(file, id): Item` — test `open` → `ok`, `closedAt`.
  - `view(items, plans: {name, label}[]): { tests: PlanGroup[], todos: TodoGroup[] }` avec
    `PlanGroup = { plan: string|null, label: string, tasks: { task: string|null, items: Item[] }[] }` et
    `TodoGroup = { group: string|null, label: string, items: Item[] }` ; seuls les éléments `open`.
  - `refsBlock(items, text): string` — `''` si aucun `#XXXX` connu.
  - `WEIGHTS = ['high', 'medium', 'low']`, `ID_ALPHABET`.

Erreurs : id inconnu → `not-found` ; `kind`, `weight`, `state` de fermeture hors liste, `text` vide → `invalid` ;
`tickTest` sur un TODO ou un test non `open`, `closeTodo` sur un test ou un TODO non `open`, `reopenItem` sur un
élément `open` ou `removed` → `state` ; toute mutation sur un fichier illisible → `unreadable` (rien d'écrit).
